# 발표 코칭 구현 및 검증

## 작업 기준

`main`의 `44e7900`에서 `codex/presentation-coach`를 만들었습니다. 원래 작업 폴더의 `fix/agent`와 미저장 변경은 건드리지 않았습니다. main의 보고서 구현 이름은 `agent-report.ts`, `agent-observation-report.tsx`입니다. 기존 보고서/준비 화면/녹화/자료 업로드/세션 저장/기록/채팅 패널을 유지했습니다. 음성 분석은 지원 브라우저에서 스피커 없는 출력 경로를 사용해 출력 장치가 없어도 수집이 멈추지 않도록 했고, 음성 처리가 일시 정지된 경우 준비 화면에서 마이크를 활성화할 수 있습니다.

## 사용 흐름

발표를 종료하면 종료 시점까지 보낸 분석 요청이 끝나기를 기다리고 한 세션 보고서를 만듭니다. 준비 단계 응답은 발표 관측으로 저장하지 않습니다. 실제 구간 타임라인에서 영상으로 이동하거나, 주요 발견을 골라 코치와 연습할 수 있습니다.

코치는 발견 이유와 실제 관측을 보여주고 하나의 30초 과제를 만듭니다. ‘재연습 녹화 시작’은 기존 준비 화면으로 이어지며 사용자가 카메라/마이크를 확인하고 녹화를 시작합니다. 기존 종료 버튼과 채팅의 종료 버튼 모두 분석과 비교로 연결됩니다. 비교 후 같은 과제를 다시 수행하거나 다음 목표를 저장할 수 있습니다. 각 재시도에는 새 연습 ID가 생겨 이전 결과를 덮어쓰지 않습니다.

`session_review → finding_selected → practice_created → recording → evaluating → comparison_ready → next_goal / completed`를 서버에 저장합니다. 사용자·세션별 진행 상태, 대화, 과제, 재촬영 연결과 비교 결과를 복구합니다. 다음 발표는 실제로 선택한 이전 목표와 최근 연습 결과를 가져옵니다.

## 관측과 보고서

- `agent_report.rawSegments`와 코칭 스냅샷에 시작·종료 시간, 실제 응답 점수, confidence, 7개 패턴 출력, 음성·영상 측정값과 품질을 그대로 보존합니다. 모델과 지표 정의 버전도 저장합니다.
- 기존 품질 정의와 호환되게, 음성 또는 얼굴 중 하나라도 유효한 창만 세션 모델 점수 통계에 사용합니다. 각 측정값은 해당 모달리티의 품질 검사를 별도로 통과해야 합니다. 두 채널이 모두 충분한지 재촬영 평가에서 추가로 확인합니다.
- 시작·종료 이벤트로 겹치지 않는 시간 셀을 만들고, 겹치는 창은 해당 시간에서 평균합니다. 세션 평균은 `Σ(시간 셀 길이 × 해당 셀 점수) / 관측 시간 합집합 길이`입니다. 최고값은 유효한 원본 창의 최고값과 그 시점입니다.
- 비관측 시간은 회색 빈 구간입니다. 120개가 넘는 조밀한 시간 셀은 연속 관측 범위 안에서만 표시를 묶고, 원본은 보존합니다. 동일한 모델 응답이 반복되어도 삭제하지 않습니다.
- 결과가 없는 세션도 커버리지 0%, 평균·최고값 null인 보고서를 만듭니다. 데이터베이스의 평균값도 null이며 0점으로 채우지 않습니다.
- 낮은 모델 점수는 발표 전달력의 성적이 아닙니다. Open / Build / Core / Close는 시간 표시 구간입니다. 기존 대시보드의 평균 배수로 만든 가상 구간 그래프도 제거했습니다.

## 의사결정과 안전한 대화 UI

기존 Luxia 의사결정·논문 검색·인용/문안 검증을 유지합니다. 선택된 항목은 실제 측정 변화와 독립 관측으로 다시 검증하며 최대 3개입니다. 모델 점수나 높은 목소리만으로 원인이나 문제를 정하지 않습니다. 모델이 설정되지 않은 경우의 대체 경로는 모든 원본 측정값을 검토하여 겹치지 않는 앞선 관측 2개와 이후 변화 관측 2개를 요구합니다. 기준 대비 10% 변화는 검토 후보를 위한 제품 규칙이며 임상 기준이 아닙니다.

채팅은 인증된 사용자의 서버 스냅샷만 읽습니다. 브라우저가 전달한 대화 상태를 진실로 사용하지 않습니다. 자유 질문을 해석할 때 LLM은 허용된 의도와 저장된 상태만으로 행동을 고를 수 있고, 사용자용 사실·수치·컴포넌트를 작성할 수 없습니다. 실제 문장과 카드는 검증된 저장 자료에서 서버가 구성합니다. 알 수 없는 질문에는 자료로 답할 수 없다고 설명합니다.

Pydantic의 구분된 컴포넌트 계약과 추가 검증이 모르는 종류, 다른 세션, 없는 발견, 실제 관측이 아닌 영상 구간, 변조된 과제·비교 수치를 거부합니다. 프론트는 switch로 허용된 카드만 렌더링하고 HTML/React 코드를 실행하지 않습니다. revision을 사용해 다른 탭의 상태 덮어쓰기를 방지합니다.

## 재연습 평가 기준

같은 모델·지표 정의 버전과 환경에서 동일 지표를 동일한 시간 가중 방식으로 계산합니다. 원본은 선택된 관측 범위, 재촬영은 재촬영 전체를 사용합니다. 각 시도에 독립 관측 2개, 커버리지 50% 이상과 해당 측정 품질 80% 이상이 필요합니다. 비교 과정의 전체 채널 품질도 80%를 요구합니다.

선택 목표의 기준값이 있을 때 `편차 감소율 = 1 - |현재값 - 기준값| / |이전값 - 기준값|`로 평가합니다. 20% 이상은 ‘달성’, 0% 초과는 ‘부분 달성’, 그 외는 ‘재시도 권장’입니다. 기준값·측정값·독립 관측이 부족하거나 버전/환경이 다르면 ‘자료 부족’입니다. 공식을 화면에 공개하며 전달력 향상이나 실제 감정의 판정으로 사용하지 않습니다. 모델 점수와 공통 음성/영상/패턴 출력의 변화, 관측 수와 품질도 함께 보여줍니다.

## 저장과 적용

먼저 기존 보고서/영상 마이그레이션을 적용한 Supabase에 `frontend/supabase/migrations/20261027_presentation_coaching.sql`을 적용해야 합니다. 새 `coaching_sessions`는 사용자별 RLS를 사용하며 서버는 사용자 JWT와 공개 키만 사용합니다. 서비스 역할 키나 브라우저가 보낸 다른 사용자 ID는 사용하지 않습니다. 기존 발표 기록과 보고서 JSON은 읽을 수 있습니다. 기존 보고서에 원본 창이 없으면 이를 재구성하거나 만들어내지 않고 코칭 자료가 없다고 설명합니다.

보고서는 코칭 스냅샷에 자동 저장합니다. 영상과 기존 기록 목록 저장은 기존 저장 화면에서 선택합니다. 발표 기록을 삭제하면 해당 코칭 스냅샷도 정리합니다. 마이그레이션/저장 연결이 없을 때 보고서는 제공하지만 코칭 저장 실패를 명확히 표시합니다. 녹화 영상 자체는 새로고침 전 저장하지 않았다면 복원할 수 없습니다.

## 검증 명령

```sh
python -m unittest discover -s server/tests -q
npm --prefix frontend test
npm --prefix frontend run typecheck
npm --prefix frontend run build -- --webpack
```

브라우저 검증은 별도 Python 환경에 `fastapi pydantic numpy pillow python-dotenv PyJWT requests httpx python-multipart uvicorn imageio-ffmpeg`와 Playwright/Chrome이 필요합니다. 실제 계정·모델과 분리된 합성 입력과 메모리 저장소를 사용합니다.

```sh
python server/tests/make_coaching_media.py
PRESENSE_BROWSER_TEST=1 python -m uvicorn server.tests.coaching_browser_server:app --host 127.0.0.1 --port 8015
# 별도 터미널: 다음 환경으로 빌드 후 시작하거나 dev -- --webpack -p 3015 실행
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:8015 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=test-key NEXT_PUBLIC_INFERENCE_URL=http://127.0.0.1:8015 NEXT_PUBLIC_SIGNAL_SOURCE=live npm --prefix frontend run build -- --webpack
npm --prefix frontend start -- -p 3015
node frontend/tests/coaching-browser.cjs
```

번들 Playwright를 쓰는 환경에서는 `PLAYWRIGHT_MODULE`에 그 모듈 경로를 지정할 수 있습니다. 이 검증 서버는 프로덕션 서버에 포함하지 않으며 반드시 loopback으로 실행합니다. 실제 모델 체크포인트·운영 Supabase·실제 Luxia 서비스의 종합 검증과 운영 DB 마이그레이션 실행은 별도로 필요합니다.
