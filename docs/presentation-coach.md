# 발표 코칭 구현 및 검증

## 작업 기준

`main`의 `44e7900`에서 `codex/presentation-coach`를 만들었습니다. 원래 작업 폴더의 `fix/agent`와 미저장 변경은 건드리지 않았습니다. main의 보고서 구현 이름은 `agent-report.ts`, `agent-observation-report.tsx`입니다. 기존 보고서/준비 화면/녹화/자료 업로드/세션 저장/기록/채팅 패널을 유지했습니다. 음성 분석은 지원 브라우저에서 스피커 없는 출력 경로를 사용해 출력 장치가 없어도 수집이 멈추지 않도록 했고, 음성 처리가 일시 정지된 경우 준비 화면에서 마이크를 활성화할 수 있습니다.

## 사용 흐름

발표를 종료하면 종료 시점까지 보낸 분석 요청이 끝나기를 기다리고 한 세션 보고서를 만듭니다. 준비 단계 응답은 발표 관측으로 저장하지 않습니다. 실제 구간 타임라인에서 영상으로 이동하거나, 주요 발견을 골라 코치와 연습할 수 있습니다.

코치는 발견 이유와 실제 관측을 보여주고 하나의 30초 과제를 만듭니다. ‘재연습 녹화 시작’은 기존 준비 화면으로 이어지며 사용자가 카메라/마이크를 확인하고 녹화를 시작합니다. 기존 종료 버튼과 채팅의 종료 버튼 모두 분석과 비교로 연결됩니다. 비교 후 같은 과제를 다시 수행하거나 다음 목표를 저장할 수 있습니다. 각 재시도에는 새 연습 ID가 생겨 이전 결과를 덮어쓰지 않습니다.

`session_review → finding_selected → practice_created → recording → evaluating → comparison_ready → next_goal / completed`를 서버에 저장합니다. 사용자·세션별 진행 상태, 대화, 과제, 재촬영 연결과 비교 결과를 복구합니다. 다음 발표는 실제로 선택한 이전 목표와 최근 연습 결과를 가져옵니다.

## 관측과 보고서

- `agent_report.rawSegments`와 코칭 스냅샷에 시작·종료 시간, 실제 응답 점수, confidence, 7개 패턴 출력, 음성·영상 측정값과 품질을 그대로 보존합니다. 모델과 지표 정의 버전도 저장합니다.
- 기존 품질 정의와 호환되게, 음성 또는 얼굴 중 하나라도 유효한 창만 세션 모델 점수 통계에 사용합니다. 각 측정값은 해당 모달리티의 품질 검사를 별도로 통과해야 합니다. 두 채널이 모두 충분한지 재촬영 평가에서 추가로 확인합니다.
- 시작·종료 이벤트로 겹치지 않는 시간 셀을 만들고, 겹치는 창은 해당 시간에서 평균합니다. 세션 평균은 `Σ(시간 셀 길이 × 해당 셀 점수) / 관측 시간 합집합 길이`입니다. 최고값은 유효한 원본 창의 최고값과 그 시점입니다.
- 비관측 시간은 회색 빈 구간입니다. 120개가 넘는 조밀한 시간 셀은 연속 관측 범위 안에서만 표시를 묶고, 원본은 보존합니다. 동일한 모델 응답이 반복되어도 삭제하지 않습니다.
- 결과가 없는 세션도 커버리지 0%, 평균·최고값 null인 보고서를 만듭니다. 데이터베이스의 평균값도 null이며 0점으로 채우지 않습니다.
- 낮은 모델 점수는 발표 전달력의 성적이 아닙니다. Open / Build / Core / Close는 시간 표시 구간입니다. 기존 대시보드의 평균 배수로 만든 가상 구간 그래프도 제거했습니다.

## 의사결정과 안전한 대화 UI

기존 Luxia 의사결정·논문 검색·인용/문안 검증을 유지합니다. 선택된 항목은 실제 측정 변화와 독립 관측으로 다시 검증하며 최대 3개입니다. 모델 점수나 높은 목소리만으로 원인이나 문제를 정하지 않습니다. 모델이 설정되지 않은 경우의 대체 경로는 모든 원본 측정값을 검토하여 겹치지 않는 앞선 관측 2개와 이후 변화 관측 2개를 요구합니다. 기준 대비 10% 변화는 검토 후보를 위한 제품 규칙이며 임상 기준이 아닙니다.

채팅은 인증된 사용자의 서버 스냅샷만 읽습니다. 브라우저가 전달한 대화 상태를 진실로 사용하지 않습니다. 현재 Luxia가 저장된 관측·품질·과거 비교·최근 대화를 읽고 질문 의도, 기존 발견, 설명, 후속 행동과 새 연습 과제를 직접 선택·작성합니다. 숫자와 시간은 AI가 자유롭게 쓰지 않고 실제 근거 ID를 참조하며 서버가 원본 값으로 삽입합니다. 카드는 허용된 참조로만 만들고 단계 변경·비교 계산·평가 판정은 서버가 담당합니다. 별도 AI 검토와 정적 검증을 통과해야 저장하며, 연결 실패/검증 실패는 503으로 알리고 과제·단계를 변경하지 않습니다. 고정 안내를 AI 답변으로 대체하지 않습니다. 녹화 시작·종료 확인처럼 운영에 필요한 안내는 ‘기본 안내’로 구분합니다.

Pydantic의 구분된 컴포넌트 계약과 추가 검증이 모르는 종류, 다른 세션, 없는 발견, 실제 관측이 아닌 영상 구간, 변조된 과제·비교 수치를 거부합니다. 프론트는 switch로 허용된 카드만 렌더링하고 HTML/React 코드를 실행하지 않습니다. revision을 사용해 다른 탭의 상태 덮어쓰기를 방지합니다.

## 재연습 평가 기준

같은 모델·지표 정의 버전과 환경에서 동일 지표를 동일한 시간 가중 방식으로 계산합니다. 원본은 선택된 관측 범위, 재촬영은 재촬영 전체를 사용합니다. 각 시도에 독립 관측 2개, 커버리지 50% 이상과 해당 측정 품질 80% 이상이 필요합니다. 비교 과정의 전체 채널 품질도 80%를 요구합니다.

새 연습은 `evaluationMode=delivery_review`를 저장합니다. 수치 변화만으로 전달의 성공·실패를 판정하지 않으며, 충분한 비교 자료가 있으면 ‘촬영 완료 · 전달 확인’을 표시합니다. 사용자가 두 영상을 보고 선택한 전달 행동의 달성·부분 달성·재시도를 확인하면 `assessmentSource=presenter`와 함께 저장합니다. 부분 달성·재시도에는 목표에 맞는 다음 행동을 제안합니다. 자료가 부족하면 ‘자료 부족’으로 남기고 자동 점수나 달성을 만들지 않습니다.

이전 버전의 저장된 연습에만 기존 편차 감소율 공식을 호환 목적으로 유지합니다. 이 결과는 ‘이전 버전의 수치 기준 결과’로 표시하며 전달력 평가로 사용하지 않습니다. 새로운 연습에는 이 공식을 적용하지 않습니다.

## 저장과 적용

먼저 기존 보고서/영상 마이그레이션을 적용한 Supabase에 `frontend/supabase/migrations/20261027_presentation_coaching.sql`을 적용해야 합니다. 새 `coaching_sessions`는 사용자별 RLS를 사용하며 서버는 사용자 JWT와 공개 키만 사용합니다. 서비스 역할 키나 브라우저가 보낸 다른 사용자 ID는 사용하지 않습니다. 기존 발표 기록과 보고서 JSON은 읽을 수 있습니다. 기존 보고서에 원본 창이 없으면 이를 재구성하거나 만들어내지 않고 코칭 자료가 없다고 설명합니다.

보고서는 코칭 스냅샷에 자동 저장합니다. 영상과 기존 기록 목록 저장은 기존 저장 화면에서 선택합니다. 발표 기록을 삭제하면 해당 코칭 스냅샷도 정리합니다. 마이그레이션/저장 연결이 없을 때 보고서는 제공하지만 코칭 저장 실패를 명확히 표시합니다. 녹화 영상 자체는 새로고침 전 저장하지 않았다면 복원할 수 없습니다.

## 이해 가능한 요약과 코칭 분기 개선

- 사용자용 수치는 ‘스트레스 신호’의 0–100 참고 눈금으로 통일했습니다. 구간을 다시 보고 같은 조건의 시도끼리 비교하는 용도를 설명하며 실제 스트레스 비율이나 발표 실력 점수로 표현하지 않습니다. 원본 0–1 응답은 변경하지 않습니다.
- 요약과 코칭 첫 응답은 ‘어느 구간에서 무엇이 달라졌는지 → 의도한 표현이었는지 확인’으로 구성합니다. Hz 등 측정값은 상세 근거에 보존합니다. 서버 보고서에는 양 언어 `presenterSummary`도 저장합니다.
- 의도한 표현이면 교정을 강요하지 않고, 연습을 선택하면 발견별로 한 가지 목표와 세 단계 행동을 제시합니다. 재촬영 수치 비교와 사용자의 전달 확인을 구분해 저장하고, 확인 결과에 따른 다음 연습 행동을 제공합니다.
- 첫 코칭에는 가짜 대화를 넣지 않습니다. 이전 진행이 있으면 ‘저장된 코칭 이어가기’ 버튼과 복원 안내를 표시하고 이전 대화는 펼쳐 보도록 했습니다.
- 검증: 서버 테스트 102개, 프론트 테스트 31개 및 배포 빌드. 브라우저에서 새 시작, 의도한 표현 수용, 세 단계 연습, 이력 접기/복원, 한국어·영어 전환을 확인했습니다. 합성 재촬영을 실제 API로 연결해 점수가 낮아져도 자동 달성을 주지 않고 전달 확인을 요청하며, 직접 확인한 ‘부분 달성’을 구분해 저장하는 것을 확인했습니다. 이번 검증에서 실제 카메라 재촬영을 수행한 것은 아닙니다.
- 현재 수집 자료에는 발화 전사나 발표 내용이 없습니다. 문장 내용·발음·설득력을 이해한 것처럼 평가하지 않으며, 관측 변화와 전달 행동에 대한 코칭을 제공합니다.


## 실제 AI 코칭과 StressID 실행 확인 (2026-10-28)

- 사용자가 Luxia로 분석 수치·시간대·코칭 대화·이전 비교 자료를 보내도록 승인했습니다. 영상/음성 원본·계정 정보·키는 LLM 입력에 포함하지 않습니다. 실제 AI는 `luxia3-llm-32b-0731`이며 키는 서버 환경에서만 읽습니다.
- `agent/coach_ai.py`가 구조화된 계획을 받습니다. 근거 ID, 관측된 영상 참조, 현재 선택 항목, 언어, 연습 스키마와 허용 행동을 검사하고, 원인을 단정하거나 측정하지 않은 전달력/심리 상태를 주장하는 문장을 거부합니다. 별도 모델 검토는 의미 검증의 보조 장치이며 수학적 사실 보장은 서버 계산과 참조 검사에서 담당합니다.
- ‘AI가 작성한 코칭’/‘기본 안내’와 데이터 출처를 표시합니다. 한국어·영어는 한 생성 결과로 함께 저장하므로 언어 전환이 새로운 과제나 리비전을 만들지 않습니다. 연결 중 응답을 놓쳐도 서버에 저장된 최신 답변을 복구합니다.
- `server/prepare_stressid_preview.py`는 로컬 StressID Speaking 영상에서 10초 음성·16프레임을 실제 배포 모델로 처리합니다. 원본/가공 영상·분석 결과·키는 Git에 넣지 않습니다. `server/local_coaching_preview.py`는 실제 추론과 실제 AI를 사용하며 인증/저장만 로컬 미리보기로 대체합니다. `PRESENSE_LOCAL_PREVIEW=1`과 loopback 실행이 필요하며 운영 앱은 이 모듈을 가져오지 않습니다.
- 확인 영상: `2z7d_Speaking.mp4`, 60초. 5초 간격의 10초 분석창 11개, 서로 다른 실제 점수 11개, 모든 창에서 음성 유효·얼굴 검출. 합친 분석창 길이 110초를 중복 집계하지 않고 실제 60초 합집합으로 평균 0.7293을 계산했습니다. 영상과 측정값은 같은 소스이며 데이터셋 라벨을 순간 스트레스 정답처럼 사용하지 않았습니다.
- 실제 브라우저에서 Luxia 선정 이유 응답, 20초 영상 이동, AI가 새로 작성한 30초 연습, 영어 전환 시 같은 과제/단계 복구를 확인했습니다. 이번 확인에서 실제 사용자의 카메라 재촬영은 수행하지 않았습니다. 이전 합성 E2E와 별개입니다.
- 서버 테스트 114개, 프론트 테스트 31개, 배포 빌드 및 새 모듈 정적 검사 통과. 운영 Supabase 마이그레이션은 실행하지 않았습니다. 원본 발화 전사/내용/발음/설득력 평가는 제공하지 않으며 보고서의 관측 요약·수치/비교 계산은 서버가 구성하고 코칭 설명·새 과제는 AI가 작성합니다.

실제 자료 미리보기 실행 예시 (모델 의존성이 설치된 Python 환경에서 실행):

```sh
python -m server.prepare_stressid_preview --video /absolute/path/to/StressID/Videos/subject/subject_Speaking.mp4 --ffmpeg /absolute/path/to/ffmpeg --output /private/tmp/presense-stressid
PRESENSE_LOCAL_PREVIEW=1 PRESENSE_SERVER_ENV=/absolute/path/to/server/.env PRESENSE_PREVIEW_MANIFEST=/private/tmp/presense-stressid/manifest.json python -m uvicorn server.local_coaching_preview:app --host 127.0.0.1 --port 8015
```

프론트는 앞선 빌드 명령의 `8015` 환경을 사용하고 `npm --prefix frontend start -- -p 3015`로 실행합니다. 미리보기의 로그인은 로컬 예시 계정이며 운영 계정을 사용하지 않습니다. 진행 상태는 출력 디렉토리의 `coaching-state.json`에 저장합니다. 영상/모델을 바꾸면 새 출력 디렉토리를 사용해 이전 코칭을 섞지 않습니다.


## 반복 관측 개수와 영상 근거 일치 수정

- 관측을 네 개 집계하면서 상세 근거를 세 개로 자르고, 채팅에는 AI가 고른 대표 영상만 표시하던 오류를 수정했습니다. 선택된 원본 ID와 겹치지 않는 관측을 모두 보존합니다.
- 저장된 기록도 `agentRun.actions`의 실제 선택 ID와 원본 측정값으로 복구합니다. 합쳐진 시간 범위 안에 있다는 이유로 다른 창을 새 근거로 넣지 않습니다. 원본이 부족하면 이를 알리며 구간을 만들어내지 않습니다.
- 채팅은 ‘반복 관측 N개’ 묶음으로 모든 근거 시점을 표시합니다. 보고서에서도 각 시점 버튼을 바로 보여주고 상세 측정값은 펼쳐 볼 수 있습니다. AI가 대표 창을 하나 골라도 전체 근거 묶음은 생략할 수 없습니다. 서버가 카드 누락·중복·다른 항목의 근거 참조를 거부합니다.
- 기존 대화 내용, 리비전과 사용자가 선택한 코칭 단계를 유지합니다. StressID 예시의 네 구간은 00:20–00:30, 00:30–00:40, 00:40–00:50, 00:50–01:00이며 네 번째 버튼으로 실제 영상 50초 이동을 확인했습니다.
- 서버 테스트 120개, 프론트 테스트 34개와 TypeScript를 포함한 빌드 통과. 실행 중인 코칭에서 네 근거와 기존 선택이 함께 유지되는 것을 확인했습니다.
