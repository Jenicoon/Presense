# 연습 행동과 항목별 재평가

보고서의 관측 확인 → 사용자의 확인 결과 선택 → 실제 AI의 한 가지 연습 생성 → 같은 기준으로 녹화 → 원본·재촬영 비교 → 행동별 확인 → 다음 행동·재시도로 연결한다. 기존 보고서, 영상, 타임라인, 채팅과 초기 측정값은 유지한다.

연습은 강조 대비, 문장 경계, 두 방식 비교, 의미 단위, 표정 비교, 시선, 눈 주변 편안함의 일곱 방법 중 하나를 사용한다. 각 방법에 눈으로 보거나 소리로 확인할 행동 두 개를 정하고 과제에 양 언어로 저장한다. AI는 이 행동을 연습하는 구체적 단계를 작성하고 기존 구조·근거·의미 검증을 통과해야 한다. 녹화 화면으로 이동해도 같은 과제와 기준을 계속 표시한다.

재촬영 후 같은 내용과 카메라·마이크 환경인지 사용자가 확인하고, 각 행동에 실행/일부 실행/미실행/확인 어려움을 입력한다. 전부 실행은 달성, 일부 실행은 부분 달성, 모두 미실행은 재시도 권장이다. 확인할 수 없거나 비교 조건이 달라지면 자료 부족으로 평가를 보류한다. 이 결과의 출처는 사용자 자기 확인으로 표시한다. 스트레스 신호 감소나 초기값과의 차이로 전달 성공을 부여하지 않는다.

모델·지표 버전과 환경, 각 시도에 독립 관측 2개·커버리지 50%·품질 80%, 목표 측정값의 독립 관측·품질·커버리지를 확인한다. 자료가 부족하면 달성 입력을 받지 않는다. 조건 불일치가 확인되면 수치 차이도 숨긴다. 원본 관측은 보존한다.

`submit_practice_review`와 `practice_review` 컴포넌트는 저장된 과제·재촬영 ID와 두 기준에만 연결할 수 있다. 다른 시도, 임의 기준, 누락 답, 중복 제출과 한 번의 성공 버튼으로 새 과제를 평가하려는 요청은 거부한다. 기존 과제는 이전 평가 계약과 호환된다. 결과 저장은 서버 계산으로 처리해 LLM 연결 없이 가능하다.

입력 중 답은 로컬 초안으로, 제출한 결과·양 언어 기준·재시도 지시는 기존 코칭 JSON에 저장한다. 재시도는 새 과제 ID를 만들고 이전 시도의 원본·답·결과를 보존한다. 같은 기준과 확인하지 못한 행동의 구체적 지시를 다음 촬영에도 유지한다. 채팅에는 자기 확인의 출처가 명시된 사실을 제공한다.

검증은 서버 168개·프론트 52개, 타입 검사와 두 로컬 실행 빌드, 실제 브라우저의 한·영 전환·새로고침·입력 복구·부분 달성 저장·원본 20초 이동으로 수행했다. 전체 재시도와 목표 저장도 서버 테스트로 확인했다.

실제 Luxia에는 무작위 ID의 합성 exact7 측정값만 보냈다. 통과한 연습의 출처를 AI로 표시하며 자기 확인 결과는 기본 안내로 구분한다. 영상·음성·계정 정보·StressID 자료는 보내지 않았다. 요청/응답과 거부된 응답도 Git 제외 로컬 검증 폴더에 보존했다. 브라우저의 재촬영 결과와 영상은 합성 검증 자료이며 실제 카메라 촬영이 아니다. 운영 Supabase 실계정 검증과 실제 발화 내용·전달력의 자동 평가는 이번 검증에 포함되지 않는다.
