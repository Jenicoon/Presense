# 초기 측정 확인과 보고서 반영

초기값은 음성·얼굴 품질을 통과한, 서로 겹치지 않는 10초 분석 창 3개 점수의 중앙값이다. 유효한 30초가 필요하므로 품질 문제나 응답 지연이 있으면 실제 대기 시간은 더 길 수 있다. 세 개가 모이면 추가 요청과 값 변경을 멈추며, 사용자가 저장한 값을 이후 연습에 재사용한다. 모델이 달라졌거나 저장값이 유효하지 않으면 다시 측정한다. 재측정 중에는 이전 요청을 취소해 오래된 응답이 섞이지 않게 했다.

초기값을 자동으로 갱신하지 않는다. 같은 모델·비슷한 환경·충분한 커버리지의 최근 연습 3건에서 평균 분석 점수가 초기값보다 같은 방향으로 15점 이상 다르면 재측정을 제안한다. 사용자 선택 후 새 측정을 저장한 경우에만 교체한다. 15점은 앱의 안내 규칙이며 의학적 기준이 아니다.

보고서의 평균·최고·원본 분석 창은 원래 값 그대로 보존한다. 초기값을 빼서 스트레스 점수를 재정의하지 않는다. 초기 측정 시간·횟수·중앙값, 발표 평균과 최고 구간의 차이를 별도로 제공하며 주요 요약과 그래프 기준선 및 코치의 검증된 사실 목록에 넣는다. 초기값이 없거나 다른 모델의 값이면 비교하지 않았다고 표시한다. 과거 보고서는 당시 초기값 스냅샷을 유지한다.

## 실제 로컬 재작성

StressID Speaking 예시 하나의 앞 30초를 초기 측정, 뒤 30초를 발표로 분리했다. 초기 측정은 [0–10, 10–20, 20–30]초 세 창이며 발표는 그 다음 영상에서 10초 창을 5초씩 이동한 5개 결과다. 두 부분은 겹치지 않는다.

- 초기값 74.5482/100, 발표 평균 74.25/100, 최고 79.6969/100.
- 발표의 실제 관측 시간 30초, 커버리지 100%, 서로 다른 실제 응답 점수 5개.
- 초기 측정은 발표 평균 계산에 넣지 않았다. 중첩 시간도 중복 계산하지 않았다.
- 반복적으로 확인된 주요 문제는 0개다. 초기값과 다르거나 점수가 높다는 이유로 교정 과제를 만들지 않았다.
- 데이터와 영상은 로컬에만 보관하며 외부 AI에는 전송하지 않았다. 예시 초기값을 실제 사용자 보정 프로필로 저장하지 않았다.

실행 결과와 한국어 보고서는 Git에서 제외한 `local-validation/calibrated-report-20261103/`에 있다. `server.prepare_stressid_preview --calibration-seconds 30`으로 같은 방식의 로컬 재현이 가능하다. 실제 측정값이 없을 때 합성값을 실제 초기값처럼 채우지 않는다.

초기값 고정, 저장·다시 불러오기, 동일 모델 확인, 최신 3회 연습 변화 판단, 보고서·채팅 반영, 원본 점수 보존, 외부 AI 전송 차단을 테스트한다. 저장·재접속은 Supabase 호출 계약 테스트와 로컬 파일 저장으로 확인했다. 운영 Supabase에 대한 실계정 검증과 본인 카메라로 30초를 측정하는 검증은 별도로 필요하다. 기존 `20261030_user_calibrations.sql`이 적용되어 있어야 운영 저장이 동작한다.
